API Reference

OutputVault — Module
OutputVault

Storage of model runs: one folder per run, <output_root>/<branch>/res-<experdef>-<variant>/, holding a solution with the git state that produced it and result items saved after it, and queries across runs with DuckDB.

source

Runs and configuration

OutputVault.RunHandle — Type
RunHandle(variant; branch = current_branch(), experdef = "default")
RunHandle(; branch, experdef, variant)

Identifies a run, and so its folder <output_root>/<branch>/res-<experdef>-<variant>.

  • variant uses only A–Z, a–z, 0–9 and _ . + = -; a Symbol or an integer is converted with string.
  • experdef uses the same characters without -, so the folder name splits at its first hyphen.
  • branch defaults to the git branch of the active project's repository (current_branch). It may contain / (nested folders); no level may start with res- or .. Passing a branch chooses only the folder: provenance always comes from the active project's repository.

The names are checked when the handle is made.

source
OutputVault.RunPattern — Type
RunPattern(; branch = "*", experdef = "*", variant = "*")

Runs matched by globs, one per part of the run's identity: * matches within one level, ? one character, [...] one of a set of characters, and ** (in branch) any number of levels, so branch = "**" includes nested branches. Used by find_runs and query_results.

source
OutputVault.current_branch — Function
current_branch() -> String

The git branch checked out in the repository of the active project (Base.active_project()), the default branch of a RunHandle. An error on a detached HEAD or outside a repository: pass branch to RunHandle there.

OutputVault.Config — Type
Config(; output_root, table_format = nothing, native = true,
         staging_root = joinpath(output_root, ".staging"))

A project's settings, made active with set_config! or with_config.

  • output_root: the top folder of the saved runs.
  • table_format: the format of table files, e.g. OutputVault.Formats.ParquetFormat(); needed only if a table is written.
  • native: also write native.jld2, the solution as Julia objects, on solution saves.
  • staging_root: where a solution's run folder is written before it is renamed into place; on the same file system as the runs, so that the rename is atomic.

Saving and loading

OutputVault.save_solution — Function
save_solution(rf::RunHandle, solution; dirty_repo_check = :warn) -> String

Start the run rf over with solution: everything saved for the run before is replaced. The solution is written at the path solution by the storage rules (a NamedTuple (; obj, stv) gives solution/obj.jld2 and solution/stv.jld2), the git state of the active project's repository in .provenance/, and, if the configuration's native is set, the solution as Julia objects in native.jld2, one key per member of a NamedTuple.

dirty_repo_check (:warn, :error or :ignore) says what to do when the repository has uncommitted changes, or there is none. A dirty repository's staged and unstaged diffs (the latter with untracked text files, up to 1 MB) are saved in .provenance/.

The new run is written to a folder under staging_root, then renamed into place; the old run is renamed aside first and deleted last. Returns the folder holding the new run: the run's folder, or, if a rename or move failed (on Windows, open files can block them), the staging folder, with a warning that says where the new and the old run are. If only the final delete fails, the new run is in place and a warning names the old folder to delete by hand.

source
OutputVault.save_result_item — Function
save_result_item(rf::RunHandle, path, value) -> String

Write value at path in the run (levels separated by /, e.g. "stats" or "irf/ss") by the storage rules: a table file path.<ext>, a folder path/ for a NamedTuple, or path.jld2. What was at path before is replaced, a folder with everything in it. The run's solution must have been saved. Saving below an item that is a file ("irf/ss" when irf.jld2 exists) is an error. Returns the item's file or folder.

A save that fails leaves the old item as it was. On Windows, if a file of the old item is still open (a Parquet file stays open after it is read until garbage collection), the new item is saved and the old copy stays beside it under a hidden name, with a warning.

source
OutputVault.load_result_item — Function
load_result_item(rf::RunHandle, path; native = false)
load_result_item(rf::RunHandle, path, T; context = nothing)

The item at path in the run.

Without a type, its data: a table file as a StoredTable (columns and file metadata), a folder as a NamedTuple of its items in alphabetical order, and a .jld2 file as a Dict of its contents.

With a type T, the item read by read_portable_jld2(T, io; context) for a .jld2 file, and otherwise from_storage(T, data; context) of its data. The default JLD2 reader returns io["value"] without checking its type; a custom reader can validate or rebuild it. Even without a type argument, JLD2 reconstructs Julia objects stored in the file; only a custom plain-data layout avoids dependence on their original Julia types.

load_result_item(rf, "solution"; native = true) reads the native copy (native.jld2, or solution/res.jld2 in runs saved with OutputVault 0.3) with JLD2 alone, and returns a NamedTuple with one member per key. native = true is an error for other paths.

source
OutputVault.move_result_item — Function
move_result_item(rf::RunHandle, from, to)

Move the item at path from to path to within the run, unchanged. An error if nothing is at from or something is at to. Neither may be under a reserved name (solution, native). On Windows, a Parquet file stays open after it is read until garbage collection (GC.gc()), and moving it, or a folder holding it, can fail.

source
OutputVault.delete_result_item — Function
delete_result_item(rf::RunHandle, path)

Remove the item at path, in every form. An error if there is none, and for the solution and the reserved names. On Windows, a Parquet file stays open after it is read until garbage collection (GC.gc()), and deleting it fails; a folder holding it may then be removed only in part.

Storage hooks

OutputVault.to_storage — Function
to_storage(x)

The value OutputVault writes for x: a Tables.jl table (one table file), a NamedTuple (a folder, one item per member; a NamedTuple of equal-length vectors is a table) or anything else (a .jld2 file written by write_portable_jld2). Default: x itself. A package adds methods for its own types.

source
OutputVault.from_storage — Function
from_storage(::Type{T}, data; context = nothing)

Rebuild a T from the data OutputVault read back: a StoredTable for a table file, a NamedTuple of the members' data for a folder. OutputVault calls it only with a type the caller supplied. There is no generic method, so loading with a type that has none is a MethodError. context is what the caller of load_result_item passed. A .jld2 item uses read_portable_jld2 instead, without calling from_storage.

source
OutputVault.write_portable_jld2 — Function
write_portable_jld2(io, x)

Write x into the open JLD2 file io that holds a .jld2 item. A package defines methods for its types to store a portable layout (plain arrays and strings that h5py, MATLAB or later Julia code can read without the package). Without a method for its type, x is stored as the Julia object, io["value"] = x.

source
OutputVault.read_portable_jld2 — Function
read_portable_jld2(::Type{T}, io; context = nothing)

Rebuild a T from the open JLD2 file io, as written by write_portable_jld2. context supplies information needed to rebuild the object, such as its model, as passed to load_result_item. The default reader returns io["value"].

Querying

OutputVault.QueryShape — Type
QueryShape(path_pattern; keys = (), column = :column, valuetype = Float64)

A family of table items and the columns of a query over them.

  • path_pattern: an item path in which a level {name} is a placeholder; its value in each matching file becomes the output column name. "stats/{sample}" matches stats/uncond and stats/boom.
  • keys: the table columns that identify a row, copied to the output.
  • column: the output column that holds the names of the table's other columns once the table is in long form.
  • valuetype: the type of the output column value (Float64, Float32, Int64, Int32, Bool or String); every selected cell is cast to it.

query_results returns branch, experdef, variant, <placeholders…>, <keys…>, <column>, value.

source
OutputVault.query_results — Function
query_results(runs, shape::QueryShape; selections...) -> NamedTuple of vectors

The cells of the table items of shape in runs, in long form: one row per selected cell, with the columns branch, experdef, variant, <placeholders…>, <keys…>, <column>, value. runs is a RunPattern or a collection of RunHandles.

Selections are keyword arguments named after a placeholder (which picks files), a key (rows) or the shape's column (the table's columns). Each takes a value or a vector of values; a String with *, ? or [ is a glob, any other value (a Symbol always) matches exactly. Globs apply to text only; numeric keys take exact values. Without a selection a column keeps everything.

Only files of the configured table format are read, and only those of the selected runs and placeholder values. Tables of different runs are combined by column name: a column that a file lacks gives no rows for it, and so does a missing cell. Text columns come back as String, numeric keys as stored, and value as the shape's valuetype; a cell that cannot be cast is an error naming its column. Rows are ordered by run, placeholders, row of the file and column of the table.

source

Table formats

OutputVault.Formats — Module
OutputVault.Formats

Read and write Tables.jl tables with their file-level metadata, one file per table. These functions can be used without configuring a run. Load the format's I/O package before calling write_table or read_table (using Parquet2 for ParquetFormat).

A format is a type F <: AbstractTableFormat with the methods extension, format_from_extension, write_table, read_table and, optionally, iswritable.

source
OutputVault.Formats.AbstractTableFormat — Type
AbstractTableFormat

Supertype of table file formats. See OutputVault.Formats for the methods a format defines.

source
OutputVault.Formats.ParquetFormat — Type
ParquetFormat()

Parquet files, written and read with Parquet2 (needs using Parquet2). File metadata are kept in Parquet's key-value metadata. Symbol columns, which Parquet stores as strings, are listed in an entry of that metadata and come back as Symbols. Other columns are passed to Parquet2 as they are; a type it cannot store is an error from Parquet2.

source
OutputVault.Formats.StoredTable — Type
StoredTable

A table read from a file: its columns (a NamedTuple of vectors) and its file-level metadata (a Dict{String,String}). It is a Tables.jl column table (Tables.columns(t) returns the columns), and DataAPI.metadata reads the metadata.

source
OutputVault.Formats.extension — Function
extension(fmt) -> String

The file extension of the format's files, without the dot ("parquet").

source
OutputVault.Formats.format_from_extension — Function
format_from_extension(::Val{ext}) -> Union{AbstractTableFormat, Nothing}

The format whose files have the extension ext (a Symbol, without the dot), or nothing if the file is not a table file. A format's package defines the method for its own extension.

OutputVault.Formats.write_table — Function
write_table(fmt, path, table; metadata = Dict{String,String}())

Write a Tables.jl table to path with its own file-level metadata (DataAPI.metadata) merged with metadata. The file is written to a temporary name and then moved into place, so readers see either the old file or the new one. Column types the format cannot preserve are an error.
