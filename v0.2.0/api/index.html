API Reference

Runs and configuration

OutputVault.RunHandle — Type
RunHandle(economy; branch=current_branch(), experdef="default")
RunHandle(; branch, experdef, economy)

Identifies a saved run by branch, experiment definition, and economy name.

All fields are coerced to String on construction. experdef must not contain -: the run's folder is res-<experdef>-<economy>, and readers (the DuckDB macros in outputvault.sql) split it at the first hyphen. economy may contain anything.

source
OutputVault.Config — Type
Config(; output_root, table_format=nothing, solution_format=(:portable, :native),
         staging_root=joinpath(tempdir(), "OutputVault"))

A project's OutputVault settings. Where each object goes is fixed (LAYOUT); which objects are saved is chosen in each save_result call.

Arguments

  • output_root: filesystem root for all saved outputs.
  • table_format: an AbstractTableFormat (e.g. OutputVault.Formats.ParquetFormat()), needed to save tables (simulations, moments, IRFs).
  • solution_format: how the solution is saved: :portable (one file per object in a documented layout of plain arrays, readable without the code that wrote it), :native (all of the solution's objects in one JLD2 file, res.jld2, exactly as they are in Julia), or both. Other components are always portable.
  • staging_root: where save_result writes a replacing solution before moving it into place. If the move cannot be made (on Windows, files held open block it), the results stay here. Default: a folder in the system temp directory.
source
OutputVault.LAYOUT — Constant
LAYOUT

Where each saved property goes: one folder per component under the run's folder. Fixed, so that every project's runs have the same structure and tools can find objects across runs.

componentproperties
solutionobj, stv
statsstats (the moments compare_economies compares; moments by sample are saved one table per sample, stats/<sample>.<ext>)
errstatserrstats
simulationsimseries, errs
irfirf
paramsparams (the model's scalar parameters, see collect_parameters)
recursionsclaims, welfare (interpolants of recursions computed at a solution's policies; each is saved when it is computed, the solution is not touched)

Saving and loading

OutputVault.save_result — Function
save_result(cfg::AbstractConfig, rf::RunHandle, result; dirty_repo_check) -> String
save_result(rf::RunHandle, result; kwargs...) -> String

Save the properties of result that LAYOUT names, each in its component's folder under the economy folder for rf, one file per property. Which objects are saved is the caller's choice: properties that result lacks or that are nothing are not saved; properties outside the layout are ignored. Returns the folder holding the results.

The economy folder holds the results of one solution: a save that includes solution objects (obj, stv) replaces the folder, so that no results of an earlier solution remain. The new results are written to staging_root(cfg) first, then the old folder is renamed aside, the new one moved into place and the old one deleted. If a step fails (on Windows, files held open, such as ones a load memory-mapped, block renames and deletes), nothing is lost or half-deleted: a warning gives the paths, the old results stay at the economy folder, and the return value is the staging folder holding the new results. Saves without solution objects (e.g. IRFs computed later) add to the economy folder.

The solution is saved in the formats solution_format(cfg): :portable writes one file per object (as every other component), :native writes all its objects to res.jld2 with JLD2, exactly as they are. The solution folder also receives the git commit id (git_commit.txt) and, for a dirty repository, the staged and unstaged diffs (git_staged.diff, git_unstaged.diff; the latter includes untracked files). Solution objects get the commit id as provenance.

Keyword arguments

  • dirty_repo_check: :warn (default), :error, or :ignore. Controls behavior when the repository has uncommitted changes.
source
FileIO.load — Function
load(cfg::AbstractConfig, rf::RunHandle, component::Symbol; solution_format = :native, model = nothing) -> NamedTuple
load(rf::RunHandle, component::Symbol; kwargs...) -> NamedTuple

Load a saved component (see LAYOUT) and return a NamedTuple of the properties that were saved, in layout order. Objects come back as their own types (e.g. a TFI ModelSolution or SimulationPanel). The no-config form uses the module-level config.

For the solution, solution_format picks the copy that is read: :native (res.jld2, the objects exactly as they were saved; needs compatible code) or :portable (one file per object; objects that store a model, such as TFI solutions and steady states, need model, either a model or a model type, see load_solution). Other components are always portable and ignore both keywords.

find_matching_results(wildcard=...; kwargs...)

Glob the output root for folders matching wildcard, parse their names as res-{experdef}-{economy}, and return a NamedTuple of RunHandles.

Keyword arguments

  • key_format: :auto (default), :economy, :experdef_economy, or :branch_experdef_economy. :auto selects the shortest format that yields unique keys.

Model hooks

OutputVault.model_metadata — Function
model_metadata(mdl) -> NamedTuple

Plain-data description of a model: reals, strings, symbols, small numeric arrays and NamedTuples of these. Stored with portable solutions and steady states, and compared with a supplied model when one is loaded. Methods for TransitionFunctionIteration models come with its extension; overload it for models whose fields include derived objects, together with model_from_metadata.

source
OutputVault.collect_parameters — Function
collect_parameters(obj_or_model) -> MomentArray

The model's parameters as a table to save in the params component: one row per parameter, one column value. The default for TFI models (in the TransitionFunctionIteration extension) takes every scalar real or Boolean field of the model (a Boolean is 0 or 1); a project can add a method for its model type to choose differently. Save it with save_result(rf, (; params = collect_parameters(obj))).

Table formats

OutputVault.AbstractTableFormat — Type
AbstractTableFormat

How tables (simulations, moments, IRFs) are stored. A format implements table_extension(fmt), write_table_file(fmt, path, table, meta) (write the table with its own metadata plus the file-level entries meta, a Dict{String,String}) and read_table_file(fmt, path) (a Tables.jl source whose file metadata DataAPI.metadata reads). Built-in formats are in OutputVault.Formats, with their methods in package extensions; TableFormat takes the functions directly.

source

Built-in table formats. Each needs its IO package loaded (using Parquet2 for ParquetFormat), which loads the package extension that implements it.

The producer interface

For extensions that store the types of a package (Writing an Extension).

OutputVault.storage_kind — Function
storage_kind(x) -> Union{String, Nothing}

The kind OutputVault records with x, which selects the read_kind method that restores it. Producers define it for their types, namespaced by package (e.g. "TransitionFunctionIteration.ModelSolution"). Default nothing: stored with JLD2 as is.

source
OutputVault.write_object — Function
write_object(cfg, dir, name, x; provenance)

Write x into dir as name.<ext>. Producers add methods for their types, built on write_table or jld2_record so that the kind is recorded; other objects are stored with JLD2 as name.jld2. provenance holds strings identifying the run (the git commit id, for the git component).

write_table(cfg, stem, table; meta = Dict{String,String}())

Write a Tables.jl table as stem.<ext> with the config's table format, recording storage_kind(table) and the entries meta in the file's metadata.

write_table_parts(cfg, dir, name, parts::NamedTuple)

Write object name, a NamedTuple of tables, as one table per part, dir/<part>.<ext>. Each file records the object it belongs to and its position, so that loading returns the NamedTuple with its parts in order. Producers use it for objects such as moments by sample.

OutputVault.assemble_moments — Function
assemble_moments(root, moments; branch = "**", experdef = "*", economies = nothing) -> NamedTuple

Read the statistics that moments (a NamedTuple of TransitionFunctionIteration moments) need from the saved runs under the output root root, in one DuckDB query for the simulation moments (vault_stats) and one for the impulse moments (vault_irf). Returns a column table with one row per (economy, statistic): branch, experdef, economy, kind, group, variable, stat, period, value, the long form that TFI's MomentTable and compare_economies(moments, names, table) read.

branch and experdef are glob patterns that narrow the files read (only matching runs are opened); economies is an optional list of economy names to keep. Only runs that have the component are read: an economy without saved statistics (or IRFs, for impulse moments) is simply absent from the result, and the table is empty if there are none. Needs DuckDB and TransitionFunctionIteration loaded (it is implemented in a package extension).
