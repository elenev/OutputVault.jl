Saving and Loading

Configuration

A Config holds a project's settings:

using OutputVault, Parquet2

cfg = Config(
    output_root     = "/path/to/outputs",
    table_format    = OutputVault.Formats.ParquetFormat(),
    solution_format = (:portable, :native),     # the default; or :portable, or :native
)
  • output_root: where all runs are saved.
  • table_format: how tables (simulations, moments, IRFs) are stored; see Table Formats. Without one, saving a table is an error that says so.
  • solution_format: which copies of the solution to save (Runs and the Layout).
  • staging_root: where a replacing solution is written before it is moved into place (default: a folder in the system temp directory); see Replacing a run.

Every function that needs a configuration takes one as its first argument, and has a form without it that uses the active configuration. A package or script sets it once:

set_config!(cfg)                      # e.g. in a package's __init__
with_config(cfg2) do                  # scoped: the previous one is restored, even on an error
    save_result(rf, result)
end

For libraries that need more than the data in Config, a subtype of OutputVault.AbstractConfig implements output_root, and optionally table_format and solution_format.

Saving

rf = RunHandle("base"; experdef = "v1")
save_result(rf, (; obj, stv, stats, errstats, simseries, errs, irf, params))   # returns the run's folder

save_result saves the properties of the result that LAYOUT names. A property that the result lacks, or that is nothing, is not saved, and properties outside the layout are ignored, so one call can be as large or as small as you like:

save_result(rf, (; obj, stv, stats))               # without the simulation
save_result(rf, (; irf))                           # IRFs computed later: added to the folder
save_result(rf, (; claims))                        # a recursion computed later

A save with obj or stv replaces the run's folder (Runs and the Layout). The keyword dirty_repo_check (:warn, the default; :error; or :ignore) controls what happens when the repository has uncommitted changes.

Replacing a run

A save with obj or stv writes the new results to staging_root first. It then renames the old run folder to .replaced-<folder>-<time> next to it, moves the staged folder into place and deletes the renamed one. On Windows, a file held open blocks renames and deletes of its folder, and Parquet2 keeps the files it has read memory-mapped until Julia's garbage collector has run, so a load followed closely by a save can hit this. Nothing is lost or half-deleted when it does:

  • If the old folder cannot be renamed, it stays intact at the run's path, the new results stay in staging_root, a warning gives both paths, and save_result returns the staging path.
  • If only the final delete fails, the new results are in place and a warning names the leftover .replaced-* folder, which discovery and DuckDB ignore. Delete it by hand.

The cure is to release whatever holds the files (close handles, leave the folder as the working directory, let the garbage collector run) and move the staged folder into place.

Loading

load(rf, :stats)           # (stats = ...,)       the properties that were saved, in layout order
load(rf, :solution)        # (obj = ..., stv = ...)  the native copy
load(rf, :recursions)      # (claims = ..., welfare = ...) whichever exist

load returns a NamedTuple of the saved properties of a component, each restored as its own type. It is FileIO.load extended; OutputVault re-exports it. For the solution:

load(rf, :solution; solution_format = :portable, model = MyModel)    # the portable copy

A portable solution stores the model's parameters as plain data. To rebuild the Julia object, model is either a model instance, which is compared with the stored metadata (a warning lists what differs), or a model type, which is rebuilt from the metadata with model_from_metadata. Single files can be read directly with load_solution(path, model) and load_steadystate(path, model). Moment tables saved by sample load as a NamedTuple with the samples in the order they were saved.

Finding runs

get_results_folders(["base", "alt"]; experdef = "v1")   # (base = RunHandle, alt = RunHandle)
find_matching_results("main/res-v1-*")           # glob the output root, parse the folder names

find_matching_results returns a NamedTuple of RunHandles keyed by the shortest combination of names that is unique (economy, then experdef_economy, then branch_experdef_economy), or by the key_format you pass. Folders whose names do not parse as res-<experdef>-<economy> are ignored.

Where things are

output_path()                       # <output_root>/<current branch>, created if absent
OutputVault.economy_folder(rf)      # <output_root>/<branch>/res-<experdef>-<economy>
